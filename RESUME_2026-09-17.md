## Thread 1: shared-discriminator rewire

`a450d07`). Implemented §1-§6 on top of that baseline:

- `src/featureextractor.py` — `selectSharedDiscriminators` now buckets same-ortho words per group
  before covering (§3 ortho-collapse: a bucket's feasible set is the union of its members', the
  chosen feature is attributed only to its "owner", an empty-union bucket leaves *every* member
  unresolved). Added `buildDiscriminatorSelection(theory, wordIsDiscrminatedByFeature=None)` as
  the single shared entry point (§2 adapter + §4 helper), producing the same
  `dict[tuple[WordFeature,...], list[tuple[Word,...]]]` shape `greedyOptimizeDiscriminator` does.

  selection directly instead of recomputing it internally via a hardcoded
  `greedyOptimizeDiscriminator` call.
- `dictionary.py` — `__main__` computes the selection once via `buildDiscriminatorSelection` and
  reuses it for the feature-count diagnostics, `lemmaFeatureWord`/Special keypress table, and
  `satOptimizeDiscriminator` — no more chimera risk between greedy-chosen and shared-discriminator-chosen
  data feeding different parts of the printed table.
- `src/ambiguitychecker.py`, `util/completeVerbParadigms.py`, `src/verbparadigm.py` — switched to
  the shared selection too (§4/§8 — §8's open question was resolved by switching, not leaving
  verb-paradigm tooling on a documented greedy baseline).
- Tests updated for the new `satOptimizeDiscriminator` signature; two new tests in
  `src/test/featureextractor_test.py` cover the ortho-collapse bucketing (homograph pair
  collapsing to one owner; empty-union bucket leaves all members unresolved).

## Thread 2: lexicon data-quality fixes (the 7 unresolved words)

Session investigation traced each of the 7 unresolved words to one of three root causes (see
conversation for the full per-word phoneme/feature trace); fixes applied:

1. **Gender/number tagging gaps** (`resources/Lexique383.tsv`, hand-edited via `csv` module,
   touching only the `genre`/`nombre` columns on the exact row, verified via `git diff` as a
   4-line diff):
   - `dégueu` (ADJ): `genre` blank → `m` (now resolves via the `m_s` combo feature).
   - `déjanté` (the **ADJ** reading only, not the VER participle homograph which was already
     resolved): `genre` blank → `m`.
   - `zakouski` (NOM): `nombre` blank → `s`.
   - `nues` (the **ADJ** reading only, not the NOM homograph which already had `nombre=p`):
     `nombre` blank → `p`. This one looks like a genuine Lexique383 data gap (the ADJ homograph's
     row was missing a tag its NOM twin had).

2. **`casher` paradigm consolidation** — fetched the French Wiktionary entry for "casher"
   (https://fr.wiktionary.org/wiki/casher): under the 1990 spelling reform it's a fully regular
   4-form adjective (casher/cashers/cashère/cashères, m_s/m_p/f_s/f_p, all pronounced identically
   `kaSER`), vs. traditionally invariable. Decision: make "casher" the lexicon's canonical
   spelling with its own full inflection, dropping "kasher"/"cachère" as separate entries (they
   were an unresolvable spelling-ambiguity pair — grammatically 100% identical, no feature could
   ever distinguish them).
   - Investigated using the project's existing NOM/ADJ paradigm-generation machinery
     (`src/nomAdjParadigm.py`, `util/generateMissingNomAdjForms.py`,
     `resources/nomAdjModelExceptions.tsv`) first, per the task's own instruction to prefer it.
     **Didn't use it**: that pipeline requires running a whole-lexicon `MISSING_FORM` audit
     (`util/validateLexiconAgainstNomAdjParadigms.py`) cross-checked against Morphalou before its
     override tier even gets consulted, and applying it would flag/generate forms for every other
     lemma with a similar gap too — far too large a blast radius for a single-word fix. Fell back
     to hand-adding the 3 new rows directly to `resources/Lexique383.tsv` and
     `resources/LexiqueInfraCorrespondance.tsv`, cloning the column-shape from the real
     `cher`/`chers`/`chère`/`chères` paradigm (same `-er`/`-ère` phonology, verified pattern-for-
     pattern) rather than guessing derived columns.
   - **Important discovery made mid-fix**: `lexique.py` already had a `spellingVariantLemme`
     table (dated 2026-09-16, sourced from Larousse) that collapsed `kascher`/`cascher`/
     `cachère`/`casher` all onto lemme `"kasher"` — a *previous* session's deliberate decision,
     now superseded. Had to remove the `"casher": "kasher"` entry (and the other three, now
     inert) or casher's own lemme would have been silently rewritten back to `"kasher"` on every
     `lexique.py` run, undoing this fix. Updated the comment block in `lexique.py` to explain the
     supersession instead of leaving it contradicting the new state.
   - `kasher` and `cachère` dropped via `resources/lexiconExclusions.tsv` (reason
     `unpopular_spelling`), the project's existing "never reaches LexiqueMixte.tsv" mechanism —
     confirmed working (it's the same mechanism already silently suppressing `kascher`/`cascher`,
     which is how the "found kascher/cascher missing from LexiqueMixte.tsv with no obvious reason"
     dead-end resolved itself — they were already excluded there, just further down the file than
     the section first checked).

3. **`fayotte`** — added lemme `fayoter` to `resources/ambiguityIgnoreList.tsv` (reason
   `unpopular_spelling`): it's a genuine, permanent spelling collision (the rare double-t spelling
   duplicates the far more common "fayote" for the exact same ind. présent 3s slot) — this only
   suppresses it from `src/ambiguitychecker.py`'s cluster metric, **not** from
   `dictionary.py`'s discriminator selection, so it correctly still shows up as the one remaining
   unresolved word after regeneration (expected, not a bug).

**Verified after regeneration** (`python lexique.py`, then — **critically** — deleting all
**three** pickles `Dictionary.pickle` + `FirstTheory.pickle` + `FeatureDiscrimator.pickle` before
`python dictionary.py`; see the gotcha note below): unresolved words dropped from **7 to 1**
(`fayotte` only, confirmed genuine and expected). `casher`/`cashers`/`cashère`/`cashères` all
present under lemme `casher`, each resolved to its own `m_s`/`m_p`/`f_s`/`f_p` feature; `kasher`/
`cachère` no longer appear anywhere in the theory. `python -m pytest src/test/`: **415/415
passing**, unchanged from thread 1 (no test hardcodes real-lexicon word/feature counts for any of
these 7 words — the two fayotte-named fixtures in `featureextractor_test.py` are synthetic
ortho-collapse test data from thread 1, unrelated to the real lexicon).

**Gotcha rediscovered this session** (already documented once in
`scratch/reform1990/RESUME_2026-09-16.md`, bit this session too): deleting only
`FirstTheory.pickle`/`FeatureDiscrimator.pickle` is **not enough** after a lexicon change —
`Dictionary.pickle` caches the parsed `Word` objects themselves and `dictionary.py` loads it
first if present. Forgetting to delete it produced a confusing first-pass result (still 7
unresolved, `dégueu` still showing `gender=None` despite the TSV fix being correct and verified)
until all three pickles were deleted together and the ~4 extra minutes of full corpus rebuild
re-run. **Delete all three, every time the lexicon itself changes**, not just when the
selection/coloring algorithm changes (thread 1 correctly didn't need to, since it changed no word
data — only thread 2 needed the full three-pickle wipe).
