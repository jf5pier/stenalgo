# Stenalgo practice trainer

A minimal, from-scratch web app for drilling Stenalgo's generated French steno
theory on the real Starboard hardware (or any other Gemini-PR-compatible
board). Shows a virtual keyboard, drills common words or short sentences
(each word labelled with the grammatical reading its chord writes), and gives
real-time correct/incorrect feedback per stroke.

MVP scope, deliberately: no progress tracking/persistence, no lesson
curation, no WPM stats. Reloading the page always restarts at the most
frequent word.

## Stack

[Elm](https://elm-lang.org/) for all app logic (keyboard rendering, Gemini PR
packet decoding, the drill state machine) -- no runtime exceptions once it
compiles, and the friendliest compiler errors of the options considered for a
first web project. The one thing Elm cannot do is call browser APIs
directly, so a small, deliberately dumb hand-written JS file
(`js/serial.js`, ~100 lines) handles only the raw `navigator.serial`
plumbing and hands 6-byte packets to Elm over a port. Everything else --
`STENO_KEY_CHART` decoding, stroke matching, keyboard rendering -- is
ordinary Elm (`src/*.elm`).

No Node/npm/bundler is required to *run* the app; the Elm compiler
(`elm make`) is a standalone binary, and the app is otherwise plain static
files.

## Data

`public/data/keyboard-layout.json`, `public/data/practice-words.json` and
`public/data/practice-sentences.json` are generated by the main `stenalgo` repo's Python side and committed to git
here, not built from source in this directory. Regenerate them from the repo
root after `starboard3h.json` or the lexicon changes:

```bash
python -m util.export_keyboard_layout
python -m util.export_practice_words
python -m util.export_practice_sentences   # after export_practice_words: its vocabulary gate
```

The sentences themselves come from `util/candidate_sentences.jsonl`, written
once by an LLM with a per-token lemma/category/conjugation annotation (which
picks the right chord for context-dependent spellings, e.g. "sais" after
"je" vs "tu"); `export_practice_sentences` rejects any sentence whose
annotation doesn't resolve every word to exactly one drilled chord.

## Local development

```bash
elm make src/Main.elm --output=main.js
python -m http.server 8000   # any static server works, as long as it's localhost/HTTPS
```

Open `http://localhost:8000` in **Chrome or Edge**. Web Serial requires a
secure context (`localhost` or HTTPS -- not `file://`), which is why a static
server is needed even though there's no backend.

## Known limitations

- **Chromium-only.** `navigator.serial` doesn't exist in Firefox or Safari;
  the app detects this and shows a message instead of a broken Connect
  button.
- **Secure context required.** HTTPS or `localhost` only -- serving the app
  from a plain LAN IP (`http://192.168.x.x:...`) will silently lack Web
  Serial.
- **Connect requires a real click.** `requestPort()` must be triggered by a
  direct user gesture; there's no auto-connect on page load.
- **Feedback is per-stroke, not per-keypress.** Gemini PR reports one packet
  per *completed* chord (the machine's firmware already assembles it), not
  individual key-down/key-up events -- so the app can't animate which keys
  are currently held mid-chord, only flash correct/incorrect once a full
  stroke is released. This is a hardware-protocol constraint, not a shortcut.
- **The Gemini PR keymap is verified for the user's own Starboard only.**
  Other "Gemini-PR-compatible" boards implement the same wire *format* but
  may assign physical keys to bit positions differently in their own
  firmware -- `public/data/keyboard-layout.json`'s `geminiPrLabel` field
  should be treated as this board's own verified default, not a universal
  mapping.
